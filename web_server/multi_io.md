### 一、网络编程基本概念

1. ipv4：

   - 格式：`192.168.1.1` 这种**四段数字**，现在我们手机、电脑、家用宽带**基本都在用 IPv4**
2. ipv6：

   - IPv4 地址不够用了（全世界设备太多），出的**升级版地址**。格式：`2001:db8::1` 这种**冒号分隔的字母数字**
3. tcp传输控制协议：

   - 先建立连接、确认双方都在线
   - 发送数据**保证不丢包、不乱序**
   - 聊天、网页、文件传输、微信、浏览器**全是 TCP**
4. socket套接字：

   - 网络通信的通道
   - 公式记：**Socket = IP 地址 + 端口号**
     - IP：找到哪台电脑
     - 端口：找到这台电脑上**哪个软件**（比如微信 8080、网页 80）
     - 所有网络编程、手机联网、服务器对接，本质都是**创建 Socket 收发数据**。
5. udp用户数据报协议：与tcp相反

   - **TCP 是打电话**：先拨号接通、说话确认、不漏字、不顺序乱，靠谱但慢。
   - **UDP 是发广播**：**不用建立连接，直接往外扔数据**，不管对方收没收到、也不管先后顺序。只在对速度要求高的地方如在线直播，语音通话使用
6. 几种地址：

   1. `192.168.1.1`：局域网ip地址，用于局域网内部通信
   2. localhost(127.0.0.1):本地回环地址，用于本机进程通信，不经过网卡、不走网线、不走局域网
   3. 0.0.0.0：监听所有网卡、所有 IP，包括：127.0.0.1、192.168.x.x、外网 IP 全都能连我
7. listen和accept:

   - listen：你不用管客人，你只是把门打开，允许别人来排队，不会阻塞
   - accept:走到门口，亲自接一个客人进来,一直没有客户端连接会阻塞，这个才是真正连接

   为什么要设置listen和accept：**listen 让系统帮你处理排队，accept 让你自己处理客人 **，一个是内核管一直listen永久有效；一个是用户处理会阻塞
8. 文件描述符：Linux 里，每个打开的文件、网络连接、设备，都会被分配一个唯一的**文件描述符（整数编号）**，用来后续读写操作。Linux 启动程序时，会默认打开 3 个标准文件描述符：

   | 编号  | 名称       | 作用                     |
   | ----- | ---------- | ------------------------ |
   | `0` | `stdin`  | 标准输入（键盘输入）     |
   | `1` | `stdout` | 标准输出（终端打印）     |
   | `2` | `stderr` | 标准错误输出（错误信息） |

   这 3 个是**固定占用的**，所以你自己创建的第一个套接字 `socket()`，只能拿到下一个可用的编号 `3`。

   然后 `accept()` 再创建一个新的套接字，就会拿到 `4`。
9. fd和socket：

   - fd 是 Linux/Unix 系统里，**IO 操作的通用 编号**。
     - 你可以把它理解成：**系统给每一个 IO 对象发的 身份证号**。
     - 不管是普通文件、键盘、屏幕、管道，还是网络连接，只要你打开了一个可以读写的对象，系统就会给你分配一个唯一的整数（比如 0、1、2、3、4...），这个数就是 fd。
     - 程序要读写数据时，就通过这个 fd 告诉系统：“我要操作这个对象”。
   - socket 是**专门用于网络通信的 IO 对象**，本质上也是一种特殊的件。
     - 你调用 `socket()` 创建一个套接字时，系统会给它分配一个 fd（比如你之前看到的 3、4）。
     - 后续你用 `read()`/`write()`/`send()`/`recv()` 读写网络数据时，用的就是这个 fd。

- IO 是大类，fd 是 IO 的通用编号，socket 是网络通信专用的 IO 对象，用 fd 来操作。

10. 调用close()的一端会进入time_wait，比如close(client_fd)，相当于是服务端关闭，此时服务端进入time_wait，再次连接会失败
11. 函数指针和指针函数：

- 指针函数：返回值为指针的函数
- 函数指针：指向函数的起始地址
  - 不加 `()` → **函数地址 / 函数指针**，把这个函数的地址传给系统
  - 加 `()` → **立刻执行函数**，现在马上运行这个函数

完整流程图

```
主线程（只干 1 件事）：（server_fd）
socket → bind → listen → while(true) { accept() → 创建新线程 }
                                              ↓
每个子线程（干 3 件事）：（client_fd）
recv() 收数据 → send() 回数据 → close() 断开
```

### 二、select

1. select为什么要拷贝一份fd_set:

- rset:保存所有客户端的总名单
- rfds：给select用的副本会被内核修改，必须拷贝，rfds会自动删除没有事件的fd。总名单不能随意修改，只有在有新的客户端建立连接时才能修改rset

2. 为什么select性能很差

- 每次必须拷贝fd_set进入内核
- 每次需要遍历所有客户端集合，性能低

3. IO多路复用和多线程：

- IO多路复用：单线程轮询所有客户端，只有client_fd有事件的时候才处理这些client，监听了所有fd事件（包括client_fd,server_fd）
- 多线程：每来一个client就创建一个线程，主线程是server端‘

### 三、POOL

1. pollfd结构体：

   ```
   struct pollfd 
   {
    int fd;         // 你要监听的文件描述符（server_fd 或 client_fd）
    short events;   // 你想让内核帮你监听什么事件？（读？写？）
    short revents;  // 内核返回给你：实际发生了什么事件
   };
   ```
2. events和revents的区别：

   - events:你告诉内核要盯着什么事件
   - revents:内核告诉你这个fd是不是真的有数据
3. epoll_event结构体：

   ```
   struct epoll_event {
       uint32_t events;  // 要监听的事件：EPOLLIN 可读
       epoll_data_t data;// 存fd
   };
   ```
